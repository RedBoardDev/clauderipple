# ClaudeRipple·Ripple Remote 품질 개선 작업 목록

기준일: 2026-10-25. 이 문서는 작업 누락 방지를 위한 내부 인계 목록이다. 현재 코드·git·테스트 결과가 문서보다 우선한다.

## 사용자 목표와 실행 규칙

- 목표: 유명 앱을 모방하는 수준이 아니라 실제 사용의 정확성·조작감·연속성·일관성에서 높은 완성도 달성.
- 동작은 Paseo를 포함한 좋은 제품의 공개 행동을 참고하고, 대화·입력창은 공식 Claude 앱의 사용성을 참고한다. 리플 테마 유지, 외부 코드·브랜드 자산 복제 금지.
- 16시 마감은 해제됐다. 호출 수보다 결과 품질과 검증을 우선한다.
- 새 구현·조사·테스트는 DeepSeek. 메인 Astra는 판단·조율·최종 검수·커밋 담당. 새로운 Astra/Claude 워커를 시작하지 않는다.
- 메시지·지시문·대기열 원문을 요약·절단해 전송하지 않는다. 크기는 무손실 분할 전송으로 처리한다. 한계는 명시하고 실패를 숨기지 않는다.
- 운영 라우터·실설정·계정·키를 검증 대상으로 조작하지 않는다. push·배포·운영 재시작은 별도 승인 대상.
- 모바일은 `apps/ripple-remote` 별도 비공개 git 저장소다. 모바일 커밋은 그 안에서 수행한다.
- 외부 공개 한국어를 새로 쓰거나 고치면 사용자에게 2차 문구 검수 여부를 묻는다. 2026-10-25 솔 전환 후 웹 복구 안내 문구에 대해 제미나이 2차 검수 허락을 받았으나 공급자 한도 오류로 실패했다. 사용자는 이어진 질문에서 **이번 문구는 솔 최종 검수로 마무리**하도록 예외 허락했다. 다른 작업의 검수까지 상시 면제한 것은 아니다. 구현은 계속 DeepSeek.

## 상태 정의와 완료 기준

- `커밋됨`: 코드·관련 자동 검증을 통과해 커밋한 상태. 배포·실기기 합격을 뜻하지 않는다.
- `검수 중`: 구현 보고를 받았지만 메인의 검수 또는 보완이 남음.
- `진행 중`: 워커가 담당 중. 완료 알림 없이 결과를 추정하지 않는다.
- `대기`: 미착수 또는 조사·설계 필요.
- 항목은 삭제하지 말고 상태와 근거를 갱신한다. 신규 발견은 ID를 추가한다.
- 제품 완료는 구현 → 실패 재현/회귀테스트 → 타입/정적 검사 → 메인 검수 → 해당 플랫폼의 실제 화면·행동 확인 → 배포 확인을 구분한다.
- 전체 테스트 수만으로 완성도를 평가하지 않는다. 원문 유실·중복 실행·잘못된 성공·조작 불능은 모두 불합격이다.

### A05 — Desktop 업데이트 이후 피커 모델 표시 (긴급 우선)

사용자가 피커 모델 표시를 핵심 기능으로 지정했다. 기존 세션 라우팅 유지나 CLI 모델 지정은 이 기능의 대체 완료가 아니다. DeepSeek a656b8b65f23365dc의 진단·승인된 설정 복구는 완료됐다. 라이브 설정 추가 변경·CA·공식 앱 번들·앱 재시작·라우터 재시작은 별도 승인 전 금지.

- 17:47 `~/Library/Application Support/Claude-3p/configLibrary/`에 `egressProxyUrl=http://127.0.0.1:8791`만 든 새 entry와 `_meta.json`의 적용 ID를 복구했다. 원본 `{}`+개행은 `_meta.json.backup-20261025-174729`로 같은 폴더에 보존했다. 다른 설정·인증서·프로세스는 변경하지 않았다.
- 반영에는 Desktop 완전 종료·재실행이 필요하다(창 닫기만으로는 반영되지 않음). 실행 시점은 사용자가 정한다. 재실행 뒤 `PICKER injected`와 실제 Code 피커 목록·선택·라우팅을 각각 확인한다.
- 새 Desktop의 서명 카탈로그(`downloads.claude.ai/model-catalog/v1/catalog.json`)·`model_selector_state`·`cc` surface 경로는 미대응이다. 프록시 복구 뒤에도 목록이 없으면 이 경로를 근거로 저장소 패치를 검토한다. 설정이 사라진 원인은 미확정이다.

- 2026-10-25 17:38 실제 조회: Desktop 3.6556.2, 내장 CLI 2.1.308, 운영 라우터 0.12.14. CLI proxy는 리플을 가리키고 upstream 연속 장애는 0. 이 세션의 솔/딥시크 요청은 ChatGPT/OpenCode Go에서 HTTP 200 확인.
- readiness의 문제는 `picker-proxy`. 이는 현재 원인 후보 신호이며 업데이트가 설정을 지웠다고 확정한 것은 아니다.
- 마지막 주입 기록은 17:29:38, 32개. code/ccr/ccd/cowork에는 리플 모델이 있지만 cc/code_projects_*에는 Claude만 있다. 현재 Desktop의 실제 surface 선택을 확인하기 전 허용 목록을 무작정 확대하지 않는다.
- 목표: 새 Desktop 피커에 모델 표시 → 선택 → 실제 대상 라우팅까지 확인. 일반 Chat·Voice 등 제품 범위 밖의 모델 목록은 오염시키지 않는다.
- Desktop 중단 이후 모바일 '작업 중'은 별도 진단. 현재 실제 요청이 있다는 사실만으로 과거 중단이 실패했는지 또는 모든 백그라운드 작업을 취소해야 했는지 단정하지 않는다.

A01의 초기 200바이트 요약·truncated·queue 생략 설계는 사용자가 거절했고 철회했다. 다시 도입하지 않는다. 구형 앱은 새 chunk 기능이 없으므로 기존 대용량 한계가 남는다. 최대 16MiB를 무제한 보장으로 표현하지 않는다.

### 설치 소유권 커밋 차단 사유 — 18시대 메인 검수

- `integrations.ts`의 기본홈 경로는 아직 Desktop proxy를 대상 포트 없이 제거하고 CA를 이름 기준 sweep한다. 기본홈이라는 이유만으로 공유 항목의 소유권을 인정하면 안 된다.
- `removeClientIntegrations`의 generated worker 보호는 기본홈 manifest와 비교하는 기존 범위다. 다른 임의 홈의 공유 claim까지 보존하는지 미확인이다.
- B22의 공유 Applications 실행기와 B23의 direct 슬롯 제거는 아직 미해결이다. 다른 설치의 launcher·공유 설정을 건드리지 않는지 인접 경계를 마쳐야 한다.
- Windows 조회 오류와 부재는 분리했지만 실제 Windows에서 이번 코드로 실행하지 않았다. launchd/systemd PID 조회 실패를 무프로세스로 간주해 조작하는 경로와 장시간 drain 동안 정의 교체를 재검증해야 한다.
- 기동 시 캡처된 설치 ID+PID는 구현됐으나 프로세스별 nonce까지 도입한 것은 아니다. 구 라우터의 ID/PID 부재는 제어 거부로 남으며, 기존 운영 설치의 안전한 업그레이드·복구 동선은 별도 검증이 필요하다.
- 마지막 보완은 메인이 직접 수행했고, 모든 기존 워커는 완료 상태다. 완료 보고만으로 커밋하지 않았으며 현재 CLI/router 소스·관련 tests가 미커밋 상태다. 실제 서비스/CLI 설치·제거/프로세스 신호로 검증하지 않는다.

### B06 잔여 위험 — 외부 브라우저 보호와 별개

- 원격 img/font/CSS·fetch/XHR/WS·iframe 등 외부 리소스 로드는 이번 보호 범위 밖이다. CSP는 제품 결정이 없어 추가하지 않았다.
- Android 하위 프레임은 네이티브 탐색 콜백을 거치지 않을 수 있고, RN WebView의 DownloadListener로 다운로드가 시작될 가능성도 미해결이다.
- Android의 navigationType은 클릭과 스크립트를 구분하지 못하므로 스크립트가 확인창을 요청할 수는 있다. 확인 없이 외부 브라우저를 열 수 없도록 한 상태다.
- 사용자정보가 포함된 URL은 파서가 해석한 주소 전체를 보여주지만 선두 문자열이 실제 호스트처럼 보일 수 있다. RN URL 폴리필과 Node 파서 차이 및 기기 실행은 미검증이다.

1. 양쪽 git status/log로 실제 커밋·미커밋 변경과 워커 소유파일 확인.
2. A항목의 실제 작업 상태를 확인하고 완료 보고 없이 중복 구현하지 않음.
3. B항목의 높은 위험부터 해결하면서 U항목을 독립 작업으로 병렬 진행.
4. 새 발견과 제외 사유를 이 목록에 추가. 알려진 결함을 후속으로 적었다는 이유만으로 완료 처리하지 않음.
5. 릴리스 전 관련 자동검증과 실기기 검수를 각각 기록하고 사용자 승인 후 배포.
